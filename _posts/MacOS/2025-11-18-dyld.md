# 1. Mach-O 文件的 `Load Commands` 的相关部分信息

| 标签               | 含义                                        |
| ------------------ | ------------------------------------------- |
| `LC_LOAD_DYLINKER` | Mach-O 是可执行文件时，用于指定动态链接器   |
| `LC_ID_DYLIB`      | Mach-O 是动态库文件时，用于提供其默认引用名 |
| `LC_LOAD_DYLIB`    | 表示一个依赖的共享库名称，例如 libm.so.6    |
| `LC_RPATH`         | 指定运行时查找库的路径                      |

# 2. 可执行文件执行时序与动态库加载顺序

1. 加载可执行文件
2. 加载 `LC_LOAD_DYLINKER` 指定的动态连接器
3. 加载当前 Mach-O 文件 `LC_LOAD_DYLIB` 指定的依赖，按照如下顺序
   1. 环境变量 `DYLD_LIBRARY_PATH`
   2. 根据 `LC_LOAD_DYLIB` 路径查找
      1. 写死的，直接去绝对路径位置加载
      2. `@executable_path` 可执行文件所在的路径，也相当于绝对路径
      3. `@loader_path` 当前动态库所在的路径，也相当于绝对路径
      4. `@rpath` 代表使用 `LC_RPATH` 指定的路径，按照如下顺序
         1. 主可执行文件中的 `LC_RPATH` 指定的路径
         2. 依赖链中第一个加载的动态库的 `LC_RPATH` 指定的路径
         3. 依赖链中第二个加载的动态库的 `LC_RPATH` 指定的路径
         4. ......
         5. 当前动态库中的 `LC_RPATH` 指定的路径
   3. 标准系统库路径 `/usr/lib`, `/System/Library/Frameworks`
   4. 环境变量 `DYLD_FALLBACK_LIBRARY_PATH`

**注意：对于递归的依赖，`LC_RPATH` 的生效范围是递归的，与 Linux 不同**

# 3. 检查和修改二进制的配置
## 3.1. 检查配置

```
OBJECT_NAME=MachO.dylib
otool -l OBJECT_NAME | grep -A2 LC_LOAD_DYLINKER
otool -l OBJECT_NAME | grep -A5 LC_ID_DYLIB
otool -l OBJECT_NAME | grep -A5 LC_LOAD_DYLIB
otool -l OBJECT_NAME | grep -A2 LC_RPATH
```

## 3.2. 修改配置

```shell
install_name_tool -id ID MACHO_FILE                         # 修改 LC_ID_DYLIB
install_name_tool -change LIB_ORIG LIB_NEW MACHO_FILE       # 修改 LC_LOAD_DYLIB
install_name_tool -add_rpath RPATH MACHO_FILE               # 新增 LC_RPATH
install_name_tool -rpath RPATH_ORIG RPATH_NEW MACHO_FILE    # 修改 LC_RPATH
install_name_tool -delete_rpath RPATH MACHO_FILE            # 移除 LC_RPATH

codesign --force --deep --sign - MACHO_FILE                 # 签名
```
